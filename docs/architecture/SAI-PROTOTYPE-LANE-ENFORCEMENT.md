# Sai prototype lane enforcement — **draft implementation contract for `prototype/lane-enforcement`**. Base authority: merged PR #75 on `main` at `759d017a6c6cec3960c158bb5f1e8906c200d740`; canonical prototype root is verifier-owned and exactly `prototypes/plugins/`. Goal: make the non-shipping prototype lane mechanically real without weakening production Sai authority. **Prototype design freedom:** code inside `prototypes/plugins/<plugin>/` may freely explore SwiftUI, visual values, components, layout, typography, interaction and motion. `SaiDesignLanguage` is a preferred reusable dependency when useful, not a prototype compliance requirement. `PrototypeDesign/` is an optional organizational convention, not an exemption/security boundary. No prototype-local design choice gains production authority by existing; during Integrate, surviving design is explicitly reconciled as REUSE, PROMOTE, feature-local production composition, or DROP and then passes normal production design review. Production remains locked: `featureUIAllowed=false`; non-prototype SwiftUI/design restrictions remain unchanged. **Canonical/path authority:** reject near-prefixes (`prototypes/plugin/`, `prototypes/plugins-evil/`, `prototype/plugins/`), traversal/normalization escape, symlink/filesystem indirection, root/direct-child misuse and candidate-selected roots. **One-way dependency isolation:** prototype Swift/Go may reuse approved stable Sai capabilities (`SaiDesignLanguage`, `SaiFoundation`, `SaiAPI`, stable exported production Go where mechanically visible); production Swift/Go/build graphs may never import, resolve, require or transitively depend on `prototypes/**`. Walk-discovered production `Package.swift` and `Package@swift-*.swift`, `go.mod`, `go.work`, Go imports and symlinks are checked with normalized/resolved paths and fail closed on malformed/unverifiable inputs. Prototype-scoped changes may not edit protected production Go under `cmd/sai/**` or `internal/**`; rename/copy paths and trusted-base diff failures fail closed. Prototype-local mocks/helpers are allowed but may not become production dependencies or a second Go/OpenAPI authority; genuine production capability changes belong in separate production-authority PRs. `sai-verify` owns mapping/completeness for the prototype surface; no parallel verifier or candidate-selected authority is added. The existing Sai Design Language workflow may trigger on prototype changes as the execution vehicle for structural lane checks and production design preservation, but canonical prototype design literals themselves are intentionally unrestricted. Required adversarial behavior — **FAIL:** production SwiftUI outside production authority; near-prefix/relocated prototype roots; path/symlink escape; production Apple manifests resolving into prototype code; production Go importing prototype code; prototype-scoped edits to protected production Go; unmapped prototype surfaces. **PASS:** arbitrary SwiftUI/design experimentation anywhere inside a canonical plugin (including raw colors, spacing, fonts, radii, shadows and motion); optional `PrototypeDesign/`; prototype reuse of stable Sai capabilities; pure prototype-only changes; production builds/tests with the prototype tree removed. Keep checks linear/cheap, reuse `cmd/sai-design-check` + `cmd/sai-verify`, add no production runtime dependency or generic plugin marketplace/runtime, and remain within repository PR budget. Exact-head verification/review remains required; stale evidence never counts for a newer SHA. After merge, successor work may build the smallest real native prototype under `prototypes/plugins/author/`; graduation, Foundry UX, Integrate/Spin Off execution and full Author product workflows remain out of scope for this lane-enforcement PR.
