# Prototype plugin lane enforcement
Verifier-owned non-shipping prototype-plugin lane: canonical root, prototype SwiftUI/design freedom, optional Sai design reuse, one-way dependency isolation, and CI coverage. Contract: `docs/architecture/SAI-PROTOTYPE-LANE-ENFORCEMENT.md` (PR #76); parent contract `docs/architecture/SAI-PROTOTYPE-PLUGIN-LANE.md` (PR #75).
## Sub-features
- `proto-canonical-root` `prototypes/plugins/*` exact verifier-owned prototype root; near-prefix/traversal/candidate relocation attempts fail closed in `cmd/sai-design-check`.
- `proto-swiftui-exemption` `prototypes/plugins/*` SwiftUI import permitted inside the canonical root only when `featureUIAllowed=false`; production lock unchanged elsewhere.
- `proto-design-experiment-scope` `prototypes/plugins/*` canonical prototype UI may freely use prototype-local visual values, components, layout, typography, interaction, and motion. SaiDesignLanguage is a preferred reusable dependency where useful, not a prototype compliance requirement; `PrototypeDesign/` is an optional organizational convention and never production authority.
- `proto-dependency-isolation` `cmd/sai-design-check/*` every production `Package.swift` or `Package@swift-*.swift` (walk-discovered) and all production Go may not reference/import the prototype tree; prototype Go may reuse stable production packages but not modify protected production behavior.
- `proto-ci-trigger` `.github/workflows/sai-design-language.yml` changes under `prototypes/**`, `internal/**`, `cmd/sai/**`, or `go.mod` trigger the single Sai Design Language check; when the trigger is a prototype change, the check still enforces structural isolation and production design authority but does not impose production design-literal policy inside the canonical prototype lane.
## How to get to it (user POV)
- Read `docs/architecture/SAI-PROTOTYPE-LANE-ENFORCEMENT.md`; place future prototype code under `prototypes/plugins/<plugin>/`. Prototype design may be explored directly in the plugin; use `PrototypeDesign/` only when it is useful organizationally.
## Driving it with verify-sai
- **Lane policy tests.** ::gotest ./cmd/sai-design-check/...
- **Whole kernel race.** ::gotest ./cmd/sai-verify/...
- **Design contract live.** ::exec scripts/verify-semantic-hierarchy
## Gotchas
- The prototype root is owned by verifier code, never by `design/sai-design-language.json`, plugin metadata, env vars, or build settings; candidate keys naming other roots are ignored and pinned `codePolicy` paths still fail closed. `prototypes/plugin/`, `prototypes/plugins-evil/`, `prototype/plugins/`, traversal, absolute forms, and symlink escape do not satisfy the canonical-root test. Canonical prototype SwiftUI is intentionally free to use raw/experimental design values; those choices gain no production authority and must be reconciled during graduation. `PrototypeDesign/` is optional organization, not an exemption boundary. Manifest gate: walk-discovered `Package.swift` and `Package@swift-*.swift` files (prototypes/.git/.build/.swiftpm pruned) fail on lane-resolving paths or non-literal values; unreadable trees fail closed. Go import scan uses `strconv.Unquote`; unicode-escape or unparseable import paths fail closed. Production `go.work` accepts `use(` and `replace(` without a space before `(`. The verifier's own source mentioning prototype import paths is string data, not an import declaration, so it never self-triggers the gate.
